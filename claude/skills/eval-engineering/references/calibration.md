# Calibrate before measuring

The pre-spend check, in order, for any evaluation, including one the current task did not build.

1. State the required behavior and the decision the result controls.
2. Send independently justified acceptable and realistic unacceptable fixtures, with borderline ones when the decision sits on a boundary, through the exact scoring path.
   When public exemplars are not like-for-like, write the acceptable fixture by hand for the requester's goal and degrade copies of it; the set must rank it above the incumbent and the copies below it.
3. Check inputs and intermediate results for leaked setup data, filenames, answers or scoring instructions, and for missing evidence, constant output and unrelated proxies.
4. Confirm acceptable behavior passes and the failure fails with separation larger than the observed scoring variation, at the domain's decision boundary.
5. Run the simplest plausible solution (a constant answer, a direct lookup, one unguided attempt) under the same conditions.
   If it ties the intended system: keep the result when the user task is solved adequately, add a case when the claim concerns a capability the cases omit, and repair leaks or scoring defects before comparing systems; never make a task harder only so the intended system wins.
6. Run a real target attempt, confirm output, effects, traces, usage and scoring evidence were captured, and repair checks that reward assertions, intermediate artifacts or proxies.
   A check tests substance, not presence: assert the quantity each check names is nonzero and in range.
7. Complete the remaining cases, verifying each distinct execution or scoring path.
