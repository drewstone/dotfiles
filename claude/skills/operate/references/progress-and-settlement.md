# Progress and settlement

Read this when a run continues across invocations or awaits outside assessment.

## Separate the decisions

| Decision | Evidence |
|---|---|
| Is execution active? | The execution owner's liveness and terminal records |
| Did useful research advance? | Reproduced development measurements, artifacts, or resolved questions |
| Is the result accepted? | The fixed outside acceptance process |
| May another invocation run? | The installed continuation policy, authority, and remaining bounds |

An unknown outside verdict does not establish absent research progress.
An authored progress note does not establish measured progress.
A process exit does not accept a scientific claim or finish the broader objective.

## Calibrate development progress

Inspect how the installed execution owner measures progress before choosing continuation settings.
Use its maintained measurement interface when useful work must continue while acceptance remains pending.
For Runtime, verify the installed deliverable and `checkState` contract in its owning source.
Use independently checked development measurements appropriate to the task.
Examples include additional reproduced coverage, a retained valid candidate, or a verified improvement against the frozen development baseline.
Probe both a useful change and an unchanged or invalid artifact.

Keep final acceptance separate and fixed.
An always-false acceptance placeholder cannot, by itself, distinguish useful work from stagnation.
Preserve genuine no-progress limits, deadlines, resource caps, and cancellation.
Choose bounds from the registered task and measured feedback cadence.

## Match instructions to capabilities

Compare completion instructions with the actual tools served to that invocation.
Require a submission tool only when it exists and its grant and checker are valid.
An absent tool is a configuration defect, not evidence that the agent refused to finish.
Keep an unassessed result unassessed when the execution contract permits settlement without acceptance.

Retain the materialization receipt and a small consumer proof for the installed path.
A merged source fix does not prove that a running process received it.

## Continue the objective

Read the terminal record and preserve the artifact manifest before deciding on a successor.
Carry forward checked work and name conditional or unassessed claims as such.
Record changed profiles, checks, or bounds in a new immutable registration.
Keep predecessor failures available to operators; give researchers the useful research handoff.
Continue within existing authorization without reopening choices the user already settled.
