# Reflect across a portfolio

Read this when the requested scope spans repositories or sessions with different conditions.

## Define the inspected population

Enumerate relevant projects and sessions for the requested period from actual activity and records.
Deduplicate repositories, worktrees, mirrored logs, and repeated references to the same session.
Keep the canonical repository and session identities so one event cannot become several observations.
Record unavailable transcripts and uninspected projects as coverage gaps.

Inspect current state, outcomes, prior reflections, and user corrections for each project.
Use independent readers for separable project scopes when useful, with a common evidence definition and explicit ownership.
Reconcile their coverage before aggregating.

## Compare and retain

Separate groups with different task definitions, models, resource limits, environments, or termination behavior.
Do not aggregate incompatible scores, unlike cost units, or unlinked invocation counts into one effectiveness result.
Include failed, cancelled, unresolved, and unmeasured work rather than selecting completed successes.

For each repeated problem, link the original instruction or fix, later evidence, and the reason it did not resolve the outcome.
Check whether the apparent shared cause actually holds in each project before applying one correction everywhere.
Retain project-specific exceptions justified by required behavior.

Persist one canonical reflection and index its location.
Give the supported cross-project findings, their coverage and limits, the corrections performed, and remaining decisions.
Do not duplicate all source logs or manufacture common lessons where the projects differ.
